# Kubernetes v1.37 元件版本與相容性矩陣

**資料截點：2026-10-05。** 本表將各專案最新穩定版與 Kubernetes v1.37.1 原始碼／kubeadm 預設值分開記錄；它們不是同一概念。GitHub Release 日期按官方釋出日期欄位（UTC）記錄；Go 工具鏈採用官方 release history 日期，Helm chart 使用官方 index 的 `created`，無 Release 物件時明確標出 Git tag 時間。只採納正式穩定版，排除 draft 和預釋出版本；版本號含 `alpha`、`beta` 或 `rc` 的標籤不會作為穩定版。

> **後續複核（2026-10-05）：** 本快照中的 Spinnaker 2026.1.3 列保留為當時紀錄；後續穩定版複核依版本序發現更高的 **2026.3.0**（2026-09-07），儘管較低版本 2026.2.4 發布於 2026-09-25。此項更正詳見[後續現況稽核](component-current-status.md)。本公告僅記錄此項更正；其他矩陣列與日期仍保留為該快照的歷史證據。

Kubernetes 官方 [Releases 頁面](https://kubernetes.io/releases/)顯示 v1.37.1 為當前版、釋出日期為 **2026-09-15**；官方 [GitHub Release API](https://api.github.com/repos/kubernetes/kubernetes/releases/tags/v1.37.1) 對同一標籤記錄的 `published_at` 為 **2026-09-23**。兩項官方記錄日期不一致；下表的釋出日期按 GitHub API 欄位抄錄，並保留此差異，不以一方覆蓋另一方。

## v1.37.1 的推薦固定值

1. **以 kubeadm 預設值為準**：Kubernetes v1.37.1、etcd **3.7.0**、CoreDNS **1.14.6**、pause **3.10.2**。這是同一 Kubernetes 原始碼版本中的預設值；不要用上游各專案“最新”版本悄悄覆蓋。
2. **CNI 與節點執行時是獨立選擇**：CNI plugins **1.9.1** 是 Kubernetes v1.37.1 原始碼 pin，但 kubeadm 不替你部署網路外掛。優先選已有明確 v1.37 支援證據的 Calico **3.33.0**；其官方支援表明確含 v1.37。
3. **CRI-O 選擇 v1.37 stream**：截至截點可 pin **v1.37.2**，與 Kubernetes minor 對齊；同一 minor stream 是專案安裝慣例，而非通用跨補丁相容保證。
4. **containerd / runc**：如平台選 containerd，可將 containerd **2.4.1**、runc **1.5.2** 作為上游版本參考 pin；生產採用前仍需確認發行版打包組合、CRI v1、外掛啟用和 cgroup driver 設定。當前證據不足以稱這對版本已獲 Kubernetes v1.37 相容認證。
5. **有明確 1.37 矩陣的附加元件**：Metrics Server **0.9.0**、Calico **3.33.0**、Helm **4.3.0** 分別有官方材料明確覆蓋 v1.37；NVIDIA GPU Operator **26.7.1** 的平台矩陣也明確支援 v1.33–1.37，並將 Device Plugin **0.20.1** 列為該 Operator 的元件。對沒有列出 v1.37 的 cert-manager、Istio、kube-state-metrics，不要把“最新穩定版”寫成“支援 Kubernetes 1.37”。

## 尚未解決的相容性證據

- 本表查到的 Kubernetes v1.37 明確支援宣告包括：Metrics Server 0.9.x（1.34+）、Calico 3.33（測試 1.35–1.37）、Helm 4.3.x（1.34–1.37）、NVIDIA GPU Operator 26.7.1（及其矩陣所列的 Device Plugin 0.20.1），以及 CRI-O 官方按相同 Kubernetes minor stream 安裝的慣例。kind v0.33.0 與 minikube v1.39.0 釋出均明確使用／支援 Kubernetes 1.37.0；這不代表它們釋出了 1.37.1 預設映像檔。
- Cluster Autoscaler v1.36.1 的官方相容表止於 Kubernetes 1.35.x，尚無穩定 1.37 pin；Kured 1.23 明確稱 1.37 未測試。Cilium v1.20.2 和 Envoy Gateway v1.9 的正式相容矩陣也都止於 1.36；其 `latest`／main 行不是穩定釋出的相容宣告。NVIDIA Device Plugin **standalone** v0.20.1 僅有最低版本要求、未找到單獨的當前相容矩陣；ip-masq-agent、Fluentd、Elasticsearch/Kibana、Argo Workflows、Argo CD、Flux、Velero、Linkerd OSS、Skaffold、Kompose 的當前版本均未找到肯定支援 1.37 的官方矩陣。kOps 最新穩定版為 1.36.2、Kubespray v2.32.0 預設 1.36.4；不能將這兩個工具的版本說明當作 v1.37 支援。
- cert-manager 1.21、Istio 1.31 的官方支援表止於 Kubernetes 1.36；kube-state-metrics v2.20.0 對應 client-go v1.36。CSI sidecar releases 只給最低 Kubernetes 版本、未宣告 1.37 tested/max matrix；這些最低版本不是 v1.37 相容證明。需等待上游支援表／穩定版本更新，或另行驗證後再給 v1.37 pin。
- containerd、runc、Flannel、Prometheus、Grafana、node-problem-detector 與已釋出 Traefik v3.7.13 的 Kubernetes v1.37 相容性，在本文引用的正式 release 材料中尚未找到肯定矩陣。Traefik v3.7.13 tag 文件僅承諾 Gateway API Standard v1.6.1，不是 Kubernetes 1.37 相容證據。`client-go v0.37.1` 則與 Kubernetes v1.37.1 原始碼 tag 對齊，可用於該 API 版本的 Go client 依賴，不作為叢集執行時相容認證。
- 上游最新標籤與 kubeadm 綁定版本的差異只說明版本不同；除非元件官方文件明確標示測試／支援範圍，不從版本號、時間先後或同屬 v1.37 minor 推斷相容。
