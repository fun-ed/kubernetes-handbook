# Kubernetes 201

## 擴充套件應用

透過修改 Deployment 中副本的數量（replicas），可以動態擴充套件或收縮應用：

![scale](../.gitbook/assets/scale%20%282%29.png)

這些自動擴充套件的容器會自動加入到 service 中，而收縮回收的容器也會自動從 service 中刪除。

```bash
kubectl scale --replicas=3 deployment/nginx-app
kubectl rollout status deployment/nginx-app
kubectl get deployment/nginx-app -o wide
```

## 滾動升級

早期 `kubectl rolling-update` 用於管理 ReplicationController，已不是當前工作流。使用 Deployment 更新 Pod 模板，Deployment controller 會按滾動更新策略替換 Pod：

```bash
kubectl patch deployment/nginx-app --type=merge \
  -p '{"spec":{"template":{"metadata":{"annotations":{"handbook.example.com/revision-note":"rollout-demo"}}}}}'
kubectl rollout status deployment/nginx-app
```

```yaml
  spec:
    replicas: 3
    selector:
      matchLabels:
        run: nginx-app
    strategy:
      rollingUpdate:
        maxSurge: 1
        maxUnavailable: 1
      type: RollingUpdate
```

若要更新映像檔，請先選定已核准且已驗證的目標標籤，修改 Deployment 的 Pod template 後再套用。不要以重複設定目前相同的映像檔標籤來假裝觸發更新。

使用 `kubectl rollout` 確認狀態、檢視 revision，並在確認先前版本仍適用後回復：

```bash
kubectl rollout status deployment/nginx-app
kubectl rollout history deployment/nginx-app
kubectl rollout undo deployment/nginx-app
```

## 資源限制

Kubernetes 透過 cgroups 管理容器資源。以下命令為 Deployment 中名為 `nginx-app` 的容器設定 CPU 與記憶體限制：

```bash
kubectl set resources deployment nginx-app -c=nginx-app --limits=cpu=500m,memory=128Mi
```

這相當於在 Pod template 中為該容器設定 `resources.limits`。`500m` 表示半個 CPU 核心；CPU limit 是運算時間上限，不是 CPU 使用率百分比。

這等同於在每個 Pod 中設定 resources limits：

```yaml
apiVersion: v1
kind: Pod
metadata:
  labels:
    app: nginx
  name: nginx
spec:
  containers:
    - image: nginx:1.30.5
      name: nginx
      resources:
        limits:
          cpu: "500m"
          memory: "128Mi"
```

## 健康檢查

Kubernetes 作為一個面向應用的叢集管理工具，需要確保容器在部署後確實處在正常的執行狀態。Kubernetes 提供了兩種探針（Probe，支援 exec、tcpSocket 和 http 方式）來探測容器的狀態：

* LivenessProbe：探測應用是否處於健康狀態，如果不健康則刪除並重新建立容器
* ReadinessProbe：探測應用是否啟動完成並且處於正常服務狀態，如果不正常則不會接收來自 Kubernetes Service 的流量

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: nginx
  name: nginx-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - image: nginx:1.30.5
        name: nginx-app
        resources:
          limits:
            cpu: "500m"
            memory: "128Mi"
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          timeoutSeconds: 1
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          timeoutSeconds: 1
```
