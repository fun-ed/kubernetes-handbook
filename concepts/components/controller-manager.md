# kube-controller-manager

`kube-controller-manager` runs built-in controllers that observe Kubernetes API objects and reconcile them toward their desired state. Controllers manage resources such as Deployments, Jobs, Nodes, ServiceAccounts and PersistentVolumes. A controller's actual behavior depends on enabled controllers, configuration and the resources installed in the cluster; do not assume each API resource has a controller running in every deployment.

Cloud integrations can also run a separate `cloud-controller-manager`, depending on the provider and cluster architecture. It may manage cloud-specific node, route or load-balancer resources. Follow the cluster distribution and cloud provider's supported configuration rather than adding or removing controller flags on a running cluster.

## Configuration and high availability

Controller-manager command-line flags and configuration fields change between Kubernetes versions. For a kubeadm-managed control plane, inspect the manifest generated by that kubeadm version and its matching reference. Do not reuse older command lines containing removed flags such as `--enable-dynamic-provisioning` or `--feature-gates=AllAlpha=true`.

For high availability, multiple instances use leader election so only the current leader performs active control work. The lock and startup configuration are distribution-managed; modern configurations use Lease-based coordination. Follow the target version's control-plane HA procedure rather than editing leader-election annotations manually.

## Metrics and secure serving

The old unauthenticated HTTP metrics example on port `10252` is obsolete. The upstream controller-manager secure-serving endpoint uses HTTPS and authentication/authorization; `10257` is the standard secure port, but the effective address, certificates and access policy depend on the deployed configuration. Do not expose the control-plane endpoint publicly or disable its authentication to scrape metrics. Use the cluster's documented monitoring integration and grant only the necessary metrics access.

## Node lifecycle

Node monitoring intervals, eviction behavior and toleration defaults are configured by the control plane and can vary by release and cluster topology. Avoid relying on static per-zone rates or copied controller flags; use the current [Node status and eviction documentation](https://kubernetes.io/docs/concepts/architecture/nodes/) and the command-line reference for the exact v1.37.1 deployment.
