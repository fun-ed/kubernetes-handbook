# Kubernetes v1.37 组件版本与兼容性矩阵

**资料截点：2026-10-05。** 本表将各项目最新稳定版与 Kubernetes v1.37.1 源码／kubeadm 默认值分开记录；它们不是同一概念。GitHub Release 日期按官方发布日期字段（UTC）记录；Go 工具链采用官方 release history 日期，Helm chart 使用官方 index 的 `created`，无 Release 对象时明确标出 Git tag 时间。只采纳正式稳定版，排除 draft 和预发布版本；版本号含 `alpha`、`beta` 或 `rc` 的标签不会作为稳定版。

Kubernetes 官方 [Releases 页面](https://kubernetes.io/releases/)显示 v1.37.1 为当前版、发布日期为 **2026-09-15**；官方 [GitHub Release API](https://api.github.com/repos/kubernetes/kubernetes/releases/tags/v1.37.1) 对同一标签记录的 `published_at` 为 **2026-09-23**。两项官方记录日期不一致；下表的发布日期按 GitHub API 字段抄录，并保留此差异，不以一方覆盖另一方。

## v1.37.1 的推荐固定值

1. **以 kubeadm 默认值为准**：Kubernetes v1.37.1、etcd **3.7.0**、CoreDNS **1.14.6**、pause **3.10.2**。这是同一 Kubernetes 源码版本中的默认值；不要用上游各项目“最新”版本悄悄覆盖。
2. **CNI 与节点运行时是独立选择**：CNI plugins **1.9.1** 是 Kubernetes v1.37.1 源码 pin，但 kubeadm 不替你部署网络插件。优先选已有明确 v1.37 支持证据的 Calico **3.33.0**；其官方支持表明确含 v1.37。
3. **CRI-O 选择 v1.37 stream**：截至截点可 pin **v1.37.2**，与 Kubernetes minor 对齐；同一 minor stream 是项目安装惯例，而非通用跨补丁兼容保证。
4. **containerd / runc**：如平台选 containerd，可将 containerd **2.4.1**、runc **1.5.2** 作为上游版本参考 pin；生产采用前仍需确认发行版打包组合、CRI v1、插件启用和 cgroup driver 配置。当前证据不足以称这对版本已获 Kubernetes v1.37 兼容认证。
5. **有明确 1.37 矩阵的附加组件**：Metrics Server **0.9.0**、Calico **3.33.0**、Helm **4.3.0** 分别有官方材料明确覆盖 v1.37；NVIDIA GPU Operator **26.7.1** 的平台矩阵也明确支持 v1.33–1.37，并将 Device Plugin **0.20.1** 列为该 Operator 的组件。对没有列出 v1.37 的 cert-manager、Istio、kube-state-metrics，不要把“最新稳定版”写成“支持 Kubernetes 1.37”。

## 尚未解决的兼容性证据

- 本表查到的 Kubernetes v1.37 明确支持声明包括：Metrics Server 0.9.x（1.34+）、Calico 3.33（测试 1.35–1.37）、Helm 4.3.x（1.34–1.37）、NVIDIA GPU Operator 26.7.1（及其矩阵所列的 Device Plugin 0.20.1），以及 CRI-O 官方按相同 Kubernetes minor stream 安装的惯例。kind v0.33.0 与 minikube v1.39.0 发布均明确使用／支持 Kubernetes 1.37.0；这不代表它们发布了 1.37.1 默认镜像。
- Cluster Autoscaler v1.36.1 的官方兼容表止于 Kubernetes 1.35.x，尚无稳定 1.37 pin；Kured 1.23 明确称 1.37 未测试。Cilium v1.20.2 和 Envoy Gateway v1.9 的正式兼容矩阵也都止于 1.36；其 `latest`／main 行不是稳定发布的兼容声明。NVIDIA Device Plugin **standalone** v0.20.1 仅有最低版本要求、未找到单独的当前兼容矩阵；ip-masq-agent、Fluentd、Elasticsearch/Kibana、Argo Workflows、Argo CD、Flux、Velero、Linkerd OSS、Skaffold、Kompose 的当前版本均未找到肯定支持 1.37 的官方矩阵。kOps 最新稳定版为 1.36.2、Kubespray v2.32.0 默认 1.36.4；不能将这两个工具的版本说明当作 v1.37 支持。
- cert-manager 1.21、Istio 1.31 的官方支持表止于 Kubernetes 1.36；kube-state-metrics v2.20.0 对应 client-go v1.36。CSI sidecar releases 只给最低 Kubernetes 版本、未声明 1.37 tested/max matrix；这些最低版本不是 v1.37 兼容证明。需等待上游支持表／稳定版本更新，或另行验证后再给 v1.37 pin。
- containerd、runc、Flannel、Prometheus、Grafana、node-problem-detector 与已发布 Traefik v3.7.13 的 Kubernetes v1.37 兼容性，在本文引用的正式 release 材料中尚未找到肯定矩阵。Traefik v3.7.13 tag 文档仅承诺 Gateway API Standard v1.6.1，不是 Kubernetes 1.37 兼容证据。`client-go v0.37.1` 则与 Kubernetes v1.37.1 源码 tag 对齐，可用于该 API 版本的 Go client 依赖，不作为集群运行时兼容认证。
- 上游最新标签与 kubeadm 绑定版本的差异只说明版本不同；除非组件官方文档明确标示测试／支持范围，不从版本号、时间先后或同属 v1.37 minor 推断兼容。
