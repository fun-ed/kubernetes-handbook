# Kubernetes 网络和集群性能测试

> **历史基准，不代表当前性能**：本页原始结果来自旧版 Kubernetes、Traefik 和测试环境，缺少可复现的集群版本、CNI、硬件、负载与统计方法。文中毫秒数不能作为 v1.37、CNI、云平台或生产容量规划的基准。请按当前环境重新运行测试并记录完整拓扑与工具版本。

## 复现前需要固定的条件

本文的历史步骤与数字保留为早期测试记录，不应用于证明当前产品性能。重新测试时至少记录 Kubernetes 与 runtime 版本、节点和网络硬件、CNI 与 kube-proxy backend、Ingress/Gateway 实现、工作负载镜像 digest、并发模型、请求数量、预热与重复次数。

关注分位数、吞吐、错误率与资源用量，而不是单次平均响应时间。使用对照组区分 Pod-to-Pod、ClusterIP、外部 LoadBalancer/Ingress 路径，并在代表性生产拓扑中压测。测试系统应有容量边界与停止条件，避免对共享集群造成影响。

原文中的 IP、旧 Traefik/Ingress 路径及数值只用于识别原始实验数据；不要把这些端点或结果复制到新集群。
